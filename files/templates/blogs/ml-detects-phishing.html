How ML Detects Phishing URLs

From raw URL strings to ensemble classifiers — the intelligence behind automated phishing detection.

📅 2026⏱ 8 min read🎯 Technical

The Challenge

Humans can sometimes spot a phishing URL — but attackers create thousands of new ones every day. Manual review is impossible. Machine learning models can analyse a URL in milliseconds and flag threats automatically, 24/7.

Step 1 — Feature Extraction

A raw URL is a string of text. ML models need numbers. We convert each URL into a vector of numeric features that capture its structural properties.

FeatureDescriptionPhishing Signal
lengthTotal length of the URL authority (scheme + host)Phishing URLs tend to be longer
dotsNumber of dots in the hostnameMore dots = more subdomains = suspicious
https1 if HTTPS, 0 if HTTPNo HTTPS is a strong red flag
has_ip1 if hostname is a raw IP addressLegitimate sites use domain names
has_at1 if @ symbol present in authorityBrowsers ignore everything before @
subdomainsNumber of subdomain levels3+ subdomains is suspicious
suspicious_word1 if URL contains login/verify/secure etc.Phishing pages mimic legitimate actions

Step 4 — Hybrid Scoring

The ML probability alone isn't enough. PhishIntelix combines the model score with a heuristic layer — 10+ rule-based checks including typosquatting detection, TLD analysis, URL shortener detection, and live SSL verification.

The final risk score formula:

final_score = min(ml_score × 0.7 + heuristic_score, 1.0)

This hybrid approach means a URL with zero heuristic flags can't be pushed into "Phishing" territory by the ML model alone — reducing false positives on unusual but legitimate domains.
